## Implemented and tested

- Contract summary counts now join only accounts owned by the authenticated operations tenant.

### Password reset reliability

- The one-time reset token is committed before email delivery. This prevents a sent link from pointing to a token that is rolled back if a later commit fails.
- Mail-delivery failure keeps the response generic to avoid disclosing whether an account exists.
- Added a regression test asserting token persistence before a simulated email failure.
- Result: regression test passes.

### File scanning and evidence lifecycle

- Compliance evidence verification checks that a referenced attachment has cleared its security scan before verification.

### Schema/ORM drift — resolved

The original schema consistency check reported 45 missing single-column indexes, 19 historical composite indexes that the ORM did not represent, two redundant unique-constraint declarations, and six JSON-versus-JSONB type differences.

- Added forward migration `t2u3v4w5x6_reconcile_orm_schema_drift.py` to create the 45 indexes explicitly declared by the ORM and convert the six columns to JSONB using explicit PostgreSQL casts.
- Preserved the 19 established composite/association indexes by representing them in ORM metadata rather than dropping them.
- Removed redundant ORM uniqueness declarations for `assessment_competencies` and `capability_skills`, because each pair is already the table's composite primary key. This avoids duplicative uniqueness enforcement and prevents conflicting constraint/index names.
- Applied the migration successfully to a clean database and to the already-seeded isolated validation database.
- `alembic check` now reports **No new upgrade operations detected** on both databases.
- Full API suite after migration: **189 passed**.
